یک دستور که در ان یک محصول را اضافه کنیم با ای دی که ما میخواهیم
برای افزودن یک محصول با یک ID مشخص در پایگاه‌داده، بسته به زبانی که استفاده می‌کنید، دستورات متفاوت است. رایج‌ترین آن‌ها به شرح زیر است:
۱. در SQL (پایگاه‌داده‌های رابطه‌ای مثل MySQL یا PostgreSQL)
اگر می‌خواهید مستقیماً ID را تعیین کنید، کافی است نام ستون id را در دستور INSERT بیاورید:
sql
INSERT INTO products (id, name, price) 
VALUES (101, 'نام محصول', 55000);
Use code with caution.

نکته: اگر ستون ID روی حالت Auto-increment باشد، دیتابیس معمولاً اجازه درج دستی می‌دهد، مگر اینکه تنظیمات خاصی مانع شود.
۲. در JSON (ارسال درخواست به API)
اگر از متد POST یا PUT برای اضافه کردن محصول به یک پنل یا سرور استفاده می‌کنید:
json
{
  "id": 101,
  "name": "محصول جدید",
  "price": 25000
}
Use code with caution.

۳. در لاراول (Eloquent ORM)
در فریم‌ورک لاراول می‌توانید به این صورت عمل کنید:
php
$product = new Product();
$product->id = 101; // تعیین آی‌دی به صورت دستی
$product->name = 'نام محصول';
$product->save();
Use code with caution.

۴. در MongoDB (NoSQL)
در مونگو‌دی‌بی، کلید اصلی با نام _id شناخته می‌شود:
javascript
db.products.insertOne({
  _id: 101,
  name: "نام محصول",
  price: 1200
});
Use code with caution.

کدام زبان برنامه‌نویسی یا سیستم مدیریت محتوا (مثل وردپرس) مد نظر شماست تا کد دقیق‌تر همان را بفرستم؟



ست سلامت (Health Check)
باید پاسخ {"status": "ok"} را بگیرید.
powershell
Invoke-RestMethod -Method GET -Uri http://localhost:3000/health

*۲. مشاهده لیست محصولات (List Products)
ابتدا لیست پیش‌فرض را چک کنید:
powershell
Invoke-RestMethod -Method GET -Uri http://localhost:3000/products

*۳. ایجاد محصول جدید (Create Product)
یک محصول جدید بسازید (این کار بخش Validation نام و قیمت را هم تست می‌کند):
Invoke-RestMethod -Method POST -Uri http://localhost:3000/products -Body '{"name": "Monitor", "price": 150}' -ContentType "application/json"

*۴. دریافت یک محصول خاص (Get by ID)
حالا محصولی که ساختید (احتمالاً با آی‌دی ۳) را فراخوانی کنید:
powershell
Invoke-RestMethod -Method GET -Uri http://localhost:3000/products/3

*۵. به‌روزرسانی محصول (Update Product)
قیمت یا نام محصول را تغییر دهید:
Invoke-RestMethod -Method PUT -Uri http://localhost:3000/products/3 -Body '{"price": 130}' -ContentType "application/json"

*۶. حذف محصول (Delete Product)
محصول را حذف کنید (باید کد 204 برگردد که در پاورشل معمولاً خروجی خالی نشان می‌دهد):
powershell
Invoke-RestMethod -Method DELETE -Uri http://localhost:3000/products/3

*۷. تست نهایی حذف (Verify Delete)
دوباره لیست را چک کنید تا مطمئن شوید محصول حذف شده است:
powershell
Invoke-RestMethod -Method GET -Uri http://localhost:3000/products
 در این دستور ها
برای اینکه محصول را با یک آی‌دی خاص و دلخواه (مثلاً ID شماره 500) اضافه کنید، باید از متد POST استفاده کنید و فیلد id را هم در بدنه (Body) دستور قرار دهید.
دستور PowerShell به این صورت خواهد بود:
powershell
Invoke-RestMethod -Method POST -Uri http://localhost:3000/products -Body '{"id": 500, "name": "Laptop", "price": 1200}' -ContentType "application/json"
Use code with caution.

چند نکته مهم:
پشتیبانی سرور: این دستور تنها در صورتی کار می‌کند که کد سمت سرور (Backend) شما طوری تنظیم شده باشد که اجازه دهد id توسط کاربر ارسال شود. (در برخی سیستم‌ها ID به صورت خودکار ساخته می‌شود و مقدار ارسالی شما نادیده گرفته می‌شود).
عدم تکرار: اگر آی‌دی مورد نظر شما (مثلاً ۵۰۰) از قبل در لیست محصولات وجود داشته باشد، احتمالاً با خطای Conflict یا 400 Bad Request مواجه خواهید شد.
تست صحت: بعد از اجرای دستور بالا، برای اطمینان از اینکه محصول با همین کد ساخته شده، دستور زیر را بزنید:
powershell
Invoke-RestMethod -Method GET -Uri http://localhost:3000/products/500
Use code with caution.

آیا از ابزار خاصی (مثل JSON Server یا یک پروژه تمرینی Node.js) برای اجرای این API استفاده می‌کنید؟

برای ایجاد محصول با آی‌دی ۵۰۰ در محیط ترمینالی که در تصویر دارید، دستور زیر را دقیقاً کپی و اجرا کنید:

دلیل خطای تصویر شما:
در تصویری که فرستادید، شما از دستور GET استفاده کردید. دستور GET برای خواندن است و چون محصولی با کد ۵۰۰ وجود ندارد، سرور خطای "محصول پیدا نشد" (یا مشابه آن به زبان فارسی که در تصویر به دلیل بهم ریختگی فونت ناخواناست) را برگردانده است.
مراحل پیشنهادی برای تست:
۱. ساخت محصول: ابتدا دستور POST بالا را اجرا کنید.
۲. تأیید ساخت: حالا دوباره همان دستور داخل تصویر خودتان را بزنید تا اطلاعات محصول را ببینید:
powershell
Invoke-RestMethod -Method GET -Uri http://localhost:3000/products/500
Use code with caution.

در تصویر مشخص است که شما دستور POST را برای ایجاد محصول با آی‌دی ۵۰۰ ارسال کردید، اما سرور به صورت خودکار آی‌دی 6 را به آن اختصاص داده است. این یعنی سرور شما طوری تنظیم شده که آی‌دی‌ها را خودش به ترتیب (Auto-increment) می‌سازد و به مقداری که شما می‌فرستید توجهی نمی‌کند.
برای اینکه محصول دقیقاً با همان آی‌دی که می‌خواهید ثبت شود، از دستور PUT به شکل زیر استفاده کنید:
powershell
Invoke-RestMethod -Method PUT -Uri http://localhost:3000/products/500 -Body '{"id": 500, "name": "New Laptop", "price": 1000}' -ContentType "application/json"
Use code with caution.

چرا این دستور کار می‌کند؟
در بسیاری از APIها، متد PUT برای ایجاد یک منبع در یک آدرس مشخص (در اینجا /products/500) استفاده می‌شود.
اگر از POST استفاده کنید، اکثر سرورها مقدار id ارسالی شما را نادیده می‌گیرند و اولین عدد خالیِ بعدی را انتخاب می‌کنند (که در تصویر شما عدد ۶ شده است).
تست نهایی:
بعد از اجرای دستور بالا، دوباره دستور زیر را بزنید تا مطمئن شوید محصول با کد ۵۰۰ ثبت شده است:
powershell
Invoke-RestMethod -Method GET -Uri http://localhost:3000/products/500
Use code with caution.

آیا با دستور PUT موفق شدید محصول را با آی‌دی دلخواه ذخیره کنید؟

خطای قرمزی که در تصویر می‌بینید به این دلیل است که در بدنه (Body) دستور شما، یک کوتیشن مارک (") جا افتاده است. سرور نمی‌تواند متن ناقص را بخواند و خطا می‌دهد.
دستور اصلاح شده را دقیقاً به این صورت کپی و اجرا کنید (نقل‌قولِ بعد از عدد ۵۰۰ اضافه شده است):
powershell
Invoke-RestMethod -Method PUT -Uri http://localhost:3000/products/500 -Body '{"id": "500", "name": "New Laptop", "price": 1000}' -ContentType "application/json"
Use code with caution.

دلیل خطا در تصویر شما:
در دستوری که تایپ کردید، بعد از 500 علامت " قرار نداده بودید:
❌ اشتباه شما: "id": 500 "name": ...
✅ شکل درست: "id": "500", "name": ... (حتماً ویرگول , بین فیلدها را هم بگذارید).
بعد از اجرای این دستور، برای اطمینان از ثبت محصول، دستور زیر را بزنید:
powershell
Invoke-RestMethod -Method GET -Uri http://localhost:3000/products/500
Use code with caution.

آیا با رعایت این علامت گذاری‌ها خروجی صحیح را دریافت کردید؟

در تصویر جدید، شما دستور PUT را به درستی وارد کردید، اما سرور خطای "محصول یافت نشد" (که به صورت فارسیِ بهم ریخته نمایش داده شده) را برمی‌گرداند.
علت این است که متد PUT معمولاً برای ویرایش محصولی است که از قبل وجود دارد. چون محصولی با ID شماره ۵۰۰ وجود ندارد، سرور اجازه ویرایش نمی‌دهد.
راه حل نهایی
برای اضافه کردن یک محصول جدید با همان ID دلخواه، باید از متد POST استفاده کنید. این دستور را کپی و اجرا کنید:
powershell
Invoke-RestMethod -Method POST -Uri http://localhost:3000/products -Body '{"id": 500, "name": "New Laptop", "price": 1000}' -ContentType "application/json"
Use code with caution.

چرا قبلاً با POST آی‌دی ۵۰۰ نشد؟
در تلاش‌های قبلی شما، احتمالاً سرور آی‌دی را به صورت خودکار (مثل ۶) تعیین می‌کرد. اگر با دستور بالا باز هم آی‌دی به صورت خودکار تغییر کرد، یعنی سرور شما قفل شده است تا فقط آی‌دی‌های پشت سر هم بسازد و اجازه تعیین آی‌دی دستی را به شما نمی‌دهد.
آیا دسترسی به کد برنامه‌ای که در پس‌زمینه (localhost:3000) در حال اجراست دارید تا تنظیمات آی‌دی را چک کنیم؟



به صورت خود کار تعیین میشود
با توجه به اینکه سرور شما ID را به صورت خودکار تولید می‌کند، دو راه حل برای رسیدن به هدفتان وجود دارد:
راه اول: استفاده از متد POST (اگر سرور اجازه دهد)
در اکثر سیستم‌هایی که از json-server یا پروژه‌های مشابه استفاده می‌کنند، اگر ID تکراری نباشد، می‌توانید آن را به صورت دستی بفرستید. دستور زیر را دقیقاً تست کنید:
powershell
Invoke-RestMethod -Method POST -Uri "http://localhost:3000/products" -Body '{"id": "500", "name": "New Laptop", "price": 1000}' -ContentType "application/json"
Use code with caution.

راه دوم: تغییر در فایل دیتابیس (راه حل قطعی)
اگر سرور شما (مثل فایل‌های db.json) طوری تنظیم شده که همیشه ID را خودش می‌سازد و دستور بالا کار نمی‌کند، باید به این صورت عمل کنید:
۱. توقف اجرای سرور: در ترمینالی که سرور در آن در حال اجراست (معمولاً با Node.js)، کلید Ctrl + C را بزنید.
۲. ویرایش فایل: فایل دیتابیس خود را (که احتمالاً نامش db.json یا products.json است) باز کنید.
۳. افزودن دستی: محصول را به صورت دستی در فایل متنی بنویسید:
json
{
  "id": 500,
  "name": "New Laptop",
  "price": 1000
}
Use code with caution.

۴. اجرای مجدد سرور: دوباره سرور را با دستور مربوطه اجرا کنید. حالا می‌توانید با دستور زیر آن را فراخوانی کنید:
powershell
Invoke-RestMethod -Method GET -Uri "http://localhost:3000/products/500"
Use code with caution.

آیا به فایل اصلی پروژه (مثل db.json) دسترسی دارید که ID را دستی در آن وارد کنید؟



مه فایل دیتابیس ندارام چند بار پرسیدم برم نگفتی
خب، پس شما دارید از یک سرور آماده یا کدی استفاده می‌کنید که دیتابیسش در حافظه (RAM) است یا فایلش را به شما نشان نمی‌دهد. [1]
وقتی سرور طوری تنظیم شده که آی‌دی را خودش به صورت خودکار (Auto-increment) می‌سازد، یعنی منطق برنامه‌نویسی آن به این صورت است که مقدار id ارسالی شما را نادیده می‌گیرد و عدد بعدی (مثلاً ۷، ۸ و...) را جایگزین می‌کند. [2, 3]
برای اینکه مطمئن شویم راهی برای دور زدن این موضوع هست یا نه، این دستور را امتحان کنید (در این حالت آی‌دی را به صورت متن/String می‌فرستیم):
powershell
Invoke-RestMethod -Method POST -Uri http://localhost:3000/products -Body '{"id": "500", "name": "Custom ID Test", "price": 999}' -ContentType "application/json"
Use code with caution.

اگر باز هم آی‌دی خودکار تعیین شد:
این یعنی سرور شما اجازه تعیین آی‌دی دستی را نمی‌دهد. [2] در پروژه‌های واقعی، این یک ویژگی امنیتی است تا آی‌دی‌ها تداخل پیدا نکنند. [3]
یک سوال مهم: آیا این پروژه را خودتان با کدهایی مثل Node.js یا Express ساخته‌اید یا از پکیج‌های آماده‌ای مثل json-server استفاده می‌کنید؟ (دانستن این موضوع کمک می‌کند تا بگویم کجای تنظیمات را تغییر دهید).

آیا فایلی با پسوند json. در آن پوشه پیدا کردید؟

در تصویری که فرستادید، فایل دیتابیس مستقیماً در این پوشه دیده نمی‌شود. این یعنی اطلاعات محصولات شما به احتمال زیاد در یکی از دو جای زیر است:
۱. داخل پوشه src (محتمل‌ترین حالت)
پوشه زرد رنگ src را باز کنید. معمولاً در پروژه‌های Node.js، فایل‌های اصلی برنامه و دیتابیس‌های موقت (مثل db.json یا فایلی که لیست محصولات در آن است) داخل این پوشه قرار دارند.
۲. در حافظه (Memory)
اگر داخل پوشه src هم فایلی با پسوند .json پیدا نکردید، یعنی این برنامه طوری نوشته شده که محصولات را فقط در حافظه رم نگه می‌دارد و فایلی روی هارد ندارد. در این صورت با هر بار بستن و باز کردن برنامه، محصولات پاک می‌شوند.
چطور مشکل ID را حل کنید؟
چون می‌خواهید محصولی با آی‌دی دلخواه داشته باشید و سرور شما آن را خودکار تغییر می‌دهد، این دستور «ترکیبی» را امتحان کنید. گاهی اوقات فرستادن آی‌دی به عنوان رشته (String) باعث می‌شود سرور آن را دست‌کاری نکند:
powershell
Invoke-RestMethod -Method POST -Uri "http://localhost:3000/products" -Body '{"id": "500", "name": "Test Product", "price": 100}' -ContentType "application/json"
Use code with caution.

یک پیشنهاد:
پوشه src را باز کنید و یک عکس از محتویات آن بفرستید تا دقیقاً بگویم کدام فایل را باید ویرایش کنید.
آیا در پوشه src فایلی با نام‌هایی مثل products.js یا data.json می‌بینید؟

همان‌طور که در تصویر می‌بینیم، هیچ فایل db.json یا دیتابیس جداگانه‌ای وجود ندارد. این یعنی لیست محصولات شما مستقیماً در کدهای برنامه (احتمالاً داخل فایل index.js یا پوشه lib) تعریف شده است.
در این حالت، چون سرور طوری برنامه‌نویسی شده که آی‌دی را خودکار تعیین کند (Auto-increment)، با دستورات معمولی نمی‌توانید آن را مجبور کنید آی‌دی ۵۰۰ را بپذیرد.

// src/index.js
const http = require("http");
const {
  listProducts,
  findById,
  createProduct,
  updateProduct,
  deleteProduct,
} = require("./lib/store");

const server = http.createServer((req, res) => {
  const { method, url } = req;
  res.setHeader("Content-Type", "application/json");

  // Health Check
  if (url === "/health" && method === "GET") {
    res.statusCode = 200;
    return res.end(JSON.stringify({ status: "ok" }));
  }

  // List Products
  if (url === "/products" && method === "GET") {
    res.statusCode = 200;
    return res.end(JSON.stringify(listProducts()));
  }

  // Get Single Product /products/:id
  if (url.startsWith("/products/") && method === "GET") {
    const id = url.split("/")[2];
    const product = findById(id);
    if (!product) {
      res.statusCode = 404;
      return res.end(JSON.stringify({ error: "Product is not found" }));
    }
    res.statusCode = 200;
    return res.end(JSON.stringify(product));
  }

  // Create Product (POST)
  if (url === "/products" && method === "POST") {
    let body = "";
    req.on("data", (chunk) => (body += chunk.toString()));
    req.on("end", () => {
      try {
        const data = JSON.parse(body);
        if (!data.name || data.price === undefined || data.price < 0) {
          res.statusCode = 400;
          return res.end(
            JSON.stringify({ error: "product name is not found " }),
          );
        }
        const newProduct = createProduct(data);
        res.statusCode = 201;
        res.end(JSON.stringify(newProduct));
      } catch (e) {
        res.statusCode = 400;
        res.end(JSON.stringify({ error: "JSON is wrong" }));
      }
    });
    return;
  }

  // Update Product (PUT)
  if (url.startsWith("/products/") && method === "PUT") {
    const id = url.split("/")[2];
    let body = "";
    req.on("data", (chunk) => (body += chunk.toString()));
    req.on("end", () => {
      const updated = updateProduct(id, JSON.parse(body));
      if (!updated) {
        res.statusCode = 404;
        return res.end(JSON.stringify({ error: "nothing found" }));
      }
      res.statusCode = 200;
      res.end(JSON.stringify(updated));
    });
    return;
  }

  // Delete Product (DELETE)
  if (url.startsWith("/products/") && method === "DELETE") {
    const id = url.split("/")[2];
    if (deleteProduct(id)) {
      res.statusCode = 204;
      return res.end();
    }
    res.statusCode = 404;
    return res.end(JSON.stringify({ error: "Nothing found" }));
  }
});

server.listen(3000, () => {
  console.log("Server is running on http://localhost:3000");
});

        // اگر در داده‌های ارسالی id وجود داشت، همان را بفرست، در غیر این صورت اجازه بده تابع خودش بسازد
        const newProduct = createProduct(data); 
        
        res.statusCode = 201;
        res.end(JSON.stringify(newProduct));
      } catch (e) {
        res.statusCode = 400;
        res.end(JSON.stringify({ error: "JSON is wrong" }));
      }
    });
    return;
  }
Use code with caution.

۱. مدیریت خطا: استفاده از try...catch برای JSON.parse بسیار عالی است، چون مانع از کرش کردن سرور در صورت ارسال دیتای خراب می‌شود.
۲. اعتبارسنجی: چک کردن data.price < 0 نشان می‌دهد که شما به امنیت و منطق تجاری برنامه اهمیت داده‌اید.
۳. وضعیت‌های HTTP: استفاده درست از کد 201 برای ایجاد و 204 برای حذف، کاملاً مطابق با استانداردهای RESTful است.

چون همان‌طور که در تصویر ارسالی شما مشخص بود، سیستم سعی می‌کرد دستور Invoke-WebRequest را اجرا کند که پارامتر -X را نمی‌شناسد. با اضافه کردن .exe مستقیماً از ابزار استاندارد استفاده می‌کنید. [1, 2]
آیا می‌خواهید این دستورات را در یک فایل Batch (.bat) ذخیره کنیم تا با یک کلیک همه تست‌ها انجام شود؟

برای اینکه دستورات شما با curl.exe در PowerShell بدون خطا اجرا شوند، مشکل اصلی در نحوه استفاده از علامت‌های نقل‌قول (") و فاصله‌ها است. در تصویر شما، سیستم کاراکترهای بک‌اسلش (\) و فاصله‌ها را به اشتباه به عنوان بخشی از آدرس URL تفسیر کرده است.
دستور اصلاح شده برای اضافه کردن محصول با آی‌دی ۵۰۰ را دقیقاً به این شکل کپی کنید:
bash
curl.exe -X POST http://localhost:3000/products -H "Content-Type: application/json" -d "{\"id\":500,\"name\":\"Laptop\",\"price\":1200}"
Use code with caution.

دلیل خطاهای تصویر شما و راه‌حل:
۱. حذف فاصله‌های اضافی در JSON: در دستور آخر شما، بین کلیدها و مقادیر (بعد از دو نقطه) فاصله وجود داشت. در پاورشل، بهتر است داخل بخش -d برای جلوگیری از خطای "Bad hostname" از فاصله استفاده نکنید یا کل عبارت را بسیار دقیق بنویسید.
۲. فرار از نقل‌قول (Escaping): چون کل بدنه دستور با " شروع شده، تمام نقل‌قول‌های داخلی باید به صورت \" نوشته شوند تا سیستم گیج نشود.
۳. خطای Unmatched close brace: این خطا به این دلیل بود که curl فکر می‌کرد بخش دوم JSON شما ادامه آدرس سایت است. با چسباندن محتوای داخل {} این مشکل حل می‌شود.

curl.exe -X GET http://localhost:3000/products/500
Use code with caution.

برای اینکه این علامت برود و تغییرات نهایی شوند، باید این دو دستور را در ترمینال بزنید:
bash
git add src/lib/store.js

Use code with caution.

هنوز کار نمیته دستور
علت اصلی اینکه هنوز در ترمینال خطای "JSON is wrong" می‌گیرید، این است که PowerShell در تفسیر علامت‌های نقل‌قول (") داخل دستور curl.exe بسیار بد عمل می‌کند و متن را به صورت خراب به سرور می‌فرستد. [1.1, 1.2]
برای اینکه بدون درگیری با علامت‌های \ و " محصول را با آی‌دی ۵۰۰ اضافه کنید، از دستور اختصاصی پاورشل استفاده کنید که بسیار ساده‌تر است:
دستور جایگزین (دقیقاً این را کپی و اجرا کنید):
powershell
Invoke-RestMethod -Method POST -Uri "http://localhost:3000/products" -Body '{"id": 500, "name": "Laptop", "price": 1200}' -ContentType "application/json"
Use code with caution.

چرا دستورات قبلی در تصویر شما (با curl.exe) کار نکرد؟
۱. خرابی متن (JSON is wrong): وقتی از curl.exe در پاورشل استفاده می‌کنید، علامت‌های \ به درستی به سرور نمی‌رسند. سرور شما متن را به صورت {id\:500...} دریافت می‌کند که یک فرمت غلط است. [1.2]
۲. تفسیر غلط آدرس (URL position): فاصله‌های (Space) داخل متن باعث می‌شود curl فکر کند شما دارید به چندین سایت مختلف درخواست می‌فرستید. [1.1]
تست نهایی (بعد از اجرای دستور بالا):
برای اینکه مطمئن شوید محصول با آی‌دی ۵۰۰ ثبت شده، این دستور را بزنید:
powershell
Invoke-RestMethod -Method GET -Uri "http://localhost:3000/products/500"
Use code with caution.

آیا بعد از اجرای دستور اول (Invoke-RestMethod)، اطلاعات محصول را در خروجی مشاهده کردید؟

۲. فرار از کاراکترها: در ویندوز، برای اینکه علامت " به درستی به سرور برسد، باید حتماً قبل از آن یک بک‌اسلش \ بگذارید (مثل \"id\").

const http = require('http');
const { 
  listProducts, 
  findById, 
  createProduct, 
  updateProduct, 
  deleteProduct 
} = require('./lib/store');

const server = http.createServer((req, res) => {
  const { method, url } = req;
  res.setHeader('Content-Type', 'application/json');

  // Health Check
  if (url === '/health' && method === 'GET') {
    res.statusCode = 200;
    return res.end(JSON.stringify({ status: "ok" }));
  }

  // List Products
  if (url === '/products' && method === 'GET') {
    res.statusCode = 200;
    return res.end(JSON.stringify(listProducts()));
  }

  // Get Single Product /products/:id
  if (url.startsWith('/products/') && method === 'GET') {
    const id = url.split('/')[2];
    const product = findById(id);
    if (!product) {
      res.statusCode = 404;
      return res.end(JSON.stringify({ error: "محصول پیدا نشد" }));
    }
    res.statusCode = 200;
    return res.end(JSON.stringify(product));
  }

  // Create Product (POST)
  if (url === '/products' && method === 'POST') {
    let body = '';
    req.on('data', chunk => body += chunk.toString());
    req.on('end', () => {
      try {
        const data = JSON.parse(body);
        if (!data.name || data.price === undefined || data.price < 0) {
          res.statusCode = 400;
          return res.end(JSON.stringify({ error: "نام و قیمت معتبر الزامی است" }));
        }
        const newProduct = createProduct(data);
        res.statusCode = 201;
        res.end(JSON.stringify(newProduct));
      } catch (e) {
        res.statusCode = 400;
        res.end(JSON.stringify({ error: "فرمت JSON اشتباه است" }));
      }
    });
    return;
  }

  // Update Product (PUT)
  if (url.startsWith('/products/') && method === 'PUT') {
    const id = url.split('/')[2];
    let body = '';
    req.on('data', chunk => body += chunk.toString());
    req.on('end', () => {
      const updated = updateProduct(id, JSON.parse(body));
      if (!updated) {
        res.statusCode = 404;
        return res.end(JSON.stringify({ error: "محصول یافت نشد" }));
      }
      res.statusCode = 200;
      res.end(JSON.stringify(updated));
    });
    return;
  }

  // Delete Product (DELETE)
  if (url.startsWith('/products/') && method === 'DELETE') {
    const id = url.split('/')[2];
    if (deleteProduct(id)) {
      res.statusCode = 204;
      return res.end();
    }
    res.statusCode = 404;
    return res.end(JSON.stringify({ error: "محصول یافت نشد" }));
  }
});

javascript
// دیتابیس موقت در حافظه
let products = [
  { id: 1, name: "Laptop", price: 999 },
  { id: 2, name: "Phone", price: 499 }
];

// متد GET /products
export const listProducts = (search) => {
  if (search) {
    return products.filter(p => p.name.toLowerCase().includes(search.toLowerCase()));
  }
  return products;
};

// متد GET /products/:id
export const findById = (id) => products.find(p => p.id === parseInt(id));

// متد POST /products
export const createProduct = (data) => {
  const newProduct = {
    id: products.length > 0 ? Math.max(...products.map(p => p.id)) + 1 : 1,
    name: data.name.trim(),
    price: parseFloat(data.price)
  };
  products.push(newProduct);
  return newProduct;
};

// متد PUT /products/:id
export const updateProduct = (id, data) => {
  const index = products.findIndex(p => p.id === parseInt(id));
  if (index !== -1) {
    if (data.name) products[index].name = data.name.trim();
    if (data.price !== undefined) products[index].price = parseFloat(data.price);
    return products[index];
  }
  return null;
};

// متد DELETE /products/:id
export const deleteProduct = (id) => {
  const index = products.findIndex(p => p.id === parseInt(id));
  if (index !== -1) {
    products.splice(index, 1);
    return true;
  }
  return false;
};

۲. فایل اصلی سرور: src/index.js
این فایل درخواست‌ها را تحلیل و پاسخ مناسب صادر می‌کند.
javascript
import http from 'http';
import { listProducts, findById, createProduct, updateProduct, deleteProduct } from './lib/store.js';

const server = http.createServer((req, res) => {
  const url = new URL(req.url, `http://${req.headers.host}`);
  const method = req.method;
  res.setHeader('Content-Type', 'application/json');

  // 1. GET /health
  if (url.pathname === '/health' && method === 'GET') {
    res.statusCode = 200;
    return res.end(JSON.stringify({ status: "ok" }));
  }

  // 2. GET /products (With Search)
  if (url.pathname === '/products' && method === 'GET') {
    const search = url.searchParams.get('search');
    res.statusCode = 200;
    return res.end(JSON.stringify(listProducts(search)));
  }

  // 3. GET /products/:id
  if (url.pathname.startsWith('/products/') && method === 'GET') {
    const id = url.pathname.split('/')[2];
    const product = findById(id);
    if (!product) {
      res.statusCode = 404;
      return res.end(JSON.stringify({ error: "Product not found" }));
    }
    return res.end(JSON.stringify(product));
  }

  // 4. POST /products (Validation Included)
  if (url.pathname === '/products' && method === 'POST') {
    let body = '';
    req.on('data', chunk => body += chunk);
    req.on('end', () => {
      try {
        const data = JSON.parse(body);
        // Validation: name (string, not empty) & price (number, >= 0)
        if (!data.name || typeof data.name !== 'string' || data.name.trim() === '' || 
            data.price === undefined || typeof data.price !== 'number' || data.price < 0) {
          res.statusCode = 400;
          return res.end(JSON.stringify({ error: "Invalid name or price" }));
        }
        const newProduct = createProduct(data);
        res.statusCode = 201;
        res.setHeader('Location', `/products/${newProduct.id}`); // Stretch idea
        res.end(JSON.stringify(newProduct));
      } catch {
        res.statusCode = 400;
        res.end(JSON.stringify({ error: "Invalid JSON" }));
      }
    });
    return;
  }

  // 5. PUT /products/:id
  if (url.pathname.startsWith('/products/') && method === 'PUT') {
    const id = url.pathname.split('/')[2];
    let body = '';
    req.on('data', chunk => body += chunk);
    req.on('end', () => {
      const updated = updateProduct(id, JSON.parse(body));
      if (!updated) {
        res.statusCode = 404;
        return res.end(JSON.stringify({ error: "Product not found" }));
      }
      res.end(JSON.stringify(updated));
    });
    return;
  }

  // 6. DELETE /products/:id
  if (url.pathname.startsWith('/products/') && method === 'DELETE') {
    const id = url.pathname.split('/')[2];
    if (deleteProduct(id)) {
      res.statusCode = 204; // No content
      return res.end();
    }
    res.statusCode = 404;
    return res.end(JSON.stringify({ error: "Product not found" }));
  }
});

server.listen(3000, () => console.log('🚀 Server running on http://localhost:3000'));
Use code with caution.

کدام آیپد های اپل سیم کارت میگیرن
تمام مدل‌های آیپد که با پسوند Wi-Fi + Cellular عرضه می‌شوند، از سیم‌کارت پشتیبانی می‌کنند. با این حال، شیوه استفاده از سیم‌کارت در مدل‌های جدید و قدیمی متفاوت است: 
۱. مدل‌های دارای شیار سیم‌کارت فیزیکی (Physical SIM)
تقریباً تمام مدل‌های قدیمی‌تر تا قبل از سال ۲۰۲۴ دارای شیار نانو‌سیم (Nano-SIM) هستند: 
آیپد پرو: تمام مدل‌های ۱۱ و ۱۲.۹ اینچی از نسل ۱ تا ۶ (مدل‌های ۲۰۲۲ و قبل از آن).
آیپد ایر: نسل ۲ تا ۵ (مدل‌های ۲۰۲۲ و قبل از آن).
آیپد معمولی: نسل ۵ تا ۱۰.
آیپد مینی: نسل ۴ تا ۶. 
۲. مدل‌های فقط eSIM (بدون شیار سیم‌کارت فیزیکی)
اپل در مدل‌های جدید سال ۲۰۲۴، شیار سیم‌کارت فیزیکی را حذف کرده و این دستگاه‌ها فقط از eSIM (سیم‌کارت الکترونیکی) پشتیبانی می‌کنند: 
آیپد پرو M4 (مدل‌های ۱۱ و ۱۳ اینچی ۲۰۲۴).
آیپد ایر M2 (مدل‌های ۱۱ و ۱۳ اینچی ۲۰۲۴).
آیپد مینی ۷ (مدل ۲۰۲۴). 
چگونه بفهمیم یک آیپد سیم‌کارت می‌خورد؟
بررسی ظاهری: در لبه‌های کناری دستگاه به دنبال یک حفره کوچک (جای سوزن) برای خشاب سیم‌کارت بگردید.
تنظیمات دستگاه: به مسیر Settings > General > About بروید. اگر گزینه Cellular Data یا Mobile Data را در منوی اصلی تنظیمات می‌بینید، یعنی آیپد شما مدل سیم‌کارت‌خور است.
پشت بدنه: در مدل‌های قدیمی، معمولاً یک نوار پلاستیکی (آنتن) در قسمت بالای پشت بدنه دیده می‌شود. 
نکته مهم برای ایران: از آنجایی که اپراتورهای داخلی هنوز از eSIM پشتیبانی نمی‌کنند، مدل‌های ۲۰۲۴ (فقط eSIM) در ایران قابلیت اتصال به شبکه موبایل را نخواهند داشت.
آیا مدل خاصی مد نظرتان است که بخواهید وضعیت رجیستری یا مشخصات دقیق آن را چک کنید؟
